# Worksheet: Final Projects

## Goal

Use this worksheet to confirm that you can read, run, and explain the course projects instead of only starting them blindly.

## Before You Start

- Review the final-projects lesson.
- Open at least one project folder while answering.

## Flow-1: Project Review

1. Which project is the simplest starting point?
2. Which project includes PostgreSQL and pgAdmin?
3. Which project demonstrates service-to-service communication?
4. Which project has a frontend, API, and database together?

## Flow-2: Hands-On Project Check

Pick one final project and answer:

1. What services or containers does it use?
2. What port or ports does it expose?
3. Where is the application data stored, if any?
4. What file tells Docker how to start the project?

## Flow-3: Explain the Architecture

1. Which service talks to the browser first?
2. Which service stores data, if the project has a database?
3. How do services usually find each other inside the project?

## Flow-4: Reflection

Why is changing and rebuilding a project an important part of learning Docker?
# Worksheet: Final Projects

## Part 1: Compare the Projects

For each final project, write:

1. How many containers it uses
2. Whether it uses Compose
3. Whether it uses persistent storage
4. What the main learning goal is

## Part 2: Deep Thinking

1. Which project feels easiest to understand and why?
2. Which project feels most realistic and why?
3. Which project best demonstrates service-to-service communication?

## Part 3: Your Own Project Plan

Design your own mini project.

Write down:

- The project name
- The services it needs
- Which service stores data
- Which service the user opens in a browser
- Which volume you would create
- Which environment variables you would need

## Part 4: Reflection

Write one paragraph explaining how your Docker understanding changed from lesson 1 to this point.
